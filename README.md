# ex-nihilo-OS
Простая самописная unix-like ОС для x86 (32 бита, защищённый режим).

## Что уже есть

* **boot.asm** — первый этап (ровно 512 Б): сегменты, стек, линия A20,
  чтение второго этапа в `0x7E00`, передача управления.
* **boot2.asm** — второй этап (2 сектора): **опрос карты памяти BIOS
  (`INT 15h`, `AX=E820h`)**, чтение 64 секторов ядра в `0x10000`,
  переход в защищённый режим.
* **kernel.asm** — 32-битная точка входа: сегменты, стек `0x90000`, вызов `kmain`.
* **kernel.c** — вывод в текстовый видеобуфер VGA: карта E820, объём ОЗУ,
  демонстрация `pmm_alloc` / `pmm_free`.
* **hal/pmm.asm** — менеджер физических страниц: bitmap **на всю доступную ОЗУ**
  (1 МиБ bitmap = 4 ГиБ памяти), построенный по карте E820, под спинлоком.
* **hal/spinlock.asm** — спинлок на `xchg` + варианты с сохранением прерываний.
* **tests/** — host-тест PMM: линкуется с настоящим `hal/pmm.asm` и прогоняется
  как обычная 32-битная программа.
* **fs/fat16.c** — драйвер FAT16: `open/read/write/seek/close/truncate`,
  `unlink`, `mkdir/rmdir/readdir`, `rename`. Работает через абстракцию
  `blockdev`, поэтому один и тот же код идёт в ядре и в host-тестах.
* **hal/ata.asm / hal/ata.c** — драйвер ATA PIO (LBA28): в защищённом
  режиме BIOS недоступен, поэтому диск читает и пишет само ядро.
* **tools/bootemu.py** — эмуляционная проверка всего пути (unicorn):
  BIOS → реальный режим → защищённый режим → ATA PIO → FAT16. Подменяет
  прерывания BIOS и порты ATA, проверяет LBA→CHS, попадание каждого
  сектора на своё место, побайтовое совпадение ядра и работу ФС.
* **tools/mkfatimg.py** — сборка образа: файловую систему создаёт
  независимая реализация (pyfatfs), поэтому драйвер проверяется против
  чужого кода.

## Загрузка с диска: только CHS, без LBA

Образ грузится **как дискета** (`-drive if=floppy`, `-fda`). В SeaBIOS
(`src/disk.c`, функция `floppy_13`) для дискет разрешены только
`AH=00h,01h,02h,03h,04h,05h,08h,15h,16h`; всё остальное, включая
`AH=42h` (LBA extended read), уходит в `disk_13XX()` — «не реализовано»
с `CF=1`. Поэтому LBA-чтение дискеты всегда заканчивается
`Disk read error!`.

Рабочий вариант — `INT 13h/AH=02h` с явной арифметикой LBA→CHS для
дискеты 1.44 МБ (18 секторов на дорожку, 2 головы):

```
C = LBA / 36;   H = (LBA % 36) / 18;   S = LBA % 18 + 1
```

Геометрия задана константами (`SPT`, `HEADS`), а не через
`INT 13h/AH=08h`: у флоппи BIOS берёт её из CMOS и на нестандартных
конфигурациях отдаёт неверно, а образ у нас всегда 1.44 МБ.

## Раскладка образа

| сектор | содержимое                       |
|--------|----------------------------------|
| 0      | `boot.asm` (ровно 512 Б)         |
| 1..2   | `boot2.asm` (2 сектора, 1024 Б)  |
| 3..63  | `kernel.bin` (до 61 сектора)     |
| 64..   | FAT16 на весь остаток образа     |

Константы `STAGE2_SECTORS`/`KERNEL_LBA` продублированы в `Makefile`
и в asm, поэтому `make layout-check` сверяет их: размер `boot2.bin`
обязан совпасть с `STAGE2_SECTORS`, а первый сектор ядра в образе —
с первым сектором `kernel.bin`.

## Карта памяти: INT 15h / AX=E820h

`INT 15h` с `AX=E820h` — прерывание **BIOS**, поэтому оно работает только в
реальном режиме. Ядро (`hal/pmm.asm`) уже выполняется в защищённом режиме, где
`int 0x15` уйдёт в IDT (которой у ядра нет) и приведёт к исключению. Поэтому
цепочка такая:

```
boot2.asm (16 бит, реальный режим)
    INT 15h, AX=E820h  ──цикл по EBX──►  карта в 0x0600/0x0608
                                              │
                                              ▼  (0x0600: count, 0x0608: записи по 24 Б)
hal/pmm.asm (32 бита, защищённый режим)
    pmm_init() ── разбирает E820 ──► bitmap + page_limit
```

Формат записи (ACPI 3.0, 24 байта): `base` (qword), `length` (qword),
`type` (dword; `1` — доступна ОС), `acpi_ext` (dword).

Алгоритм `pmm_init`:

1. Весь bitmap помечается занятым (**fail closed**: пока карта не разобрана,
   память не выдаётся).
2. Для каждой записи `type == 1` диапазон `[base, base+length)` освобождается,
   `page_limit` расширяется до верхней границы памяти.
3. **Заново** помечаются занятыми все области `type != 1`. Порядок важен:
   записи E820 бывают пересекающимися (базовая память кончается на `0x9FC00`,
   EBDA начинается там же — они делят страницу `0x9F000`). При обратном
   порядке эта страница оставалась «свободной».
4. Резервируются: всё до `kernel_end` (загрузчик, код, данные ядра), стек
   `0x80000..0x90000`, страница 0.
5. Если карты нет — используется нижняя граница памяти от BIOS (int 12h),
   и EBDA / VGA / BIOS ROM резервируются вручную.

`pmm_free()` проверяет, что страница **целиком** лежит в области `type == 1` и
не пересекается ни с одной областью `type != 1`. Без этой проверки можно было
«освободить» видеопамять, BIOS ROM или MMIO-дыру: они помечены тем же битом
«занято», что и выданные аллокатором страницы.

Области с `type != 1` (VGA, BIOS ROM, MMIO, дыры) остаются занятыми, поэтому
`pmm_alloc` их никогда не выдаёт — это проверяется тестами.

## Производительность аллокатора

`pmm_alloc` хранит подсказку (`alloc_hint`) о том, где закончился прошлый
поиск, поэтому N выделений подряд стоят O(N), а не O(N²). Подсказка
откатывается назад в `pmm_free`, поэтому освобождённые страницы переиспользуются.
Полный обход миллиона страниц (4 ГиБ) занимает миллисекунды.

`pmm_free_pages()` возвращает инкрементально поддерживаемый счётчик, а не
пересчитывает bitmap.

## Сборка и запуск

Нужны `nasm`, `gcc` с поддержкой `-m32`, `ld`; для запуска — `qemu-system-i386`.

```sh
make            # build/os.img — образ дискеты 1.44 МБ (boot + kernel)
make run        # запуск в QEMU
make test       # тесты PMM (в т.ч. разбор E820 и «дыр» в памяти)
```

## API PMM

| Функция | Что делает |
|---|---|
| `pmm_init()` | строит bitmap по карте E820 |
| `pmm_alloc()` | выдаёт физическую страницу (4 КиБ) или `NULL` |
| `pmm_free(addr)` | возвращает страницу (плохие адреса игнорируются) |
| `pmm_free_pages()` | свободных страниц |
| `pmm_total_pages()` | страниц в модели памяти |
| `pmm_usable_bytes()` | объём доступной ОЗУ (насыщается в `0xFFFFFFFF`) |
| `pmm_e820_entries()` | записей в карте E820 |
| `pmm_e820_usable()` | из них доступных (`type == 1`) |
| `pmm_e820_entry(i, &e)` | скопировать запись в структуру `e820_entry_t` |

## Интересная информация
ex nihilo переводится как "из ничего".

## Файловая система: FAT16 с сектора 64

Образ — жёсткий диск на 16 МиБ. FAT16 занимает всё после сектора 64.

**Почему не дискета 1.44 МБ.** FAT16 по спецификации требует не меньше
4085 кластеров, иначе файловая система обязана называться FAT12. На
дискете максимум ~2880 кластеров — честной FAT16 там не бывает.

**Почему HDD, а не дискета, для драйвера.** В защищённом режиме `INT 13h`
недоступен, поэтому диск должен читать сам kernel. Для ATA PIO это
несколько `out`/`in` и `REP INSW/OUTSW`; для контроллера флоппи (FDC)
запись требует настройки канала DMA, моторов и таймингов — на порядок
больше кода и источников ошибок ради того же результата.

**Раскладка тома** (значения из BPB образа):

| параметр | значение |
|---|---|
| сектор BPB | 64 |
| кластер | 2048 Б (4 сектора) |
| кластеров | ~8160 |
| копий FAT | 2 |

### API (`fs/fat16.h`)

```c
fat16_mount(dev, lba, &vol);

fat16_open(&vol, "/HELLO.TXT", FAT16_O_RDONLY, &f);
fat16_read(&vol, &f, buf, sizeof buf);
fat16_close(&vol, &f);

fat16_open(&vol, "/NEW.TXT", FAT16_O_WRONLY | FAT16_O_CREAT, &f);
fat16_write(&vol, &f, "data", 4);

fat16_seek / fat16_truncate / fat16_unlink / fat16_mkdir /
fat16_rmdir / fat16_readdir / fat16_rename / fat16_exists
```

Режимы: `FAT16_O_RDONLY`, `O_WRONLY`, `O_RDWR`, `O_CREAT`, `O_TRUNC`,
`O_APPEND`. Ошибки — отрицательные коды в стиле POSIX (`FAT16_ERR_NOENT`,
`FAT16_ERR_ROFS`, `FAT16_ERR_NOSPC`, …).

Ограничения, заданные осознанно: только имена 8.3 в ASCII (длинные имена
пропускаются при разборе, но не создаются), без фрагментации и без
журнала; гарантий при выключении питания посреди записи нет.

## Тесты

```
make test          # PMM (217983 проверки) + FAT16 (80 проверок) на хосте
make layout-check  # смещения boot/boot2/kernel совпадают с asm
make boottest      # эмуляция: загрузчик + ядро + ATA + FAT16
```

`make boottest` — единственный тест, проходящий весь путь. Он ловит то,
что не видно ни сборке, ни host-тестам. Например, на этом этапе он нашёл:

* загрузчик считал LBA→CHS по геометрии дискеты (18/2), а QEMU для
  маленького IDE-диска использует 63/16 — ядро читалось из чужих
  секторов. Теперь геометрия спрашивается у BIOS (`AH=08h`);
* `ata_wait_ready` разбирал регистр состояния из `AL`, куда вызывающий
  код только что положил команду `0xEC`, — диск «зависал» занятым;
* аргументы `ata_read_sector` читались из стека со смещением на слово
  больше нужного, потому что функция была без прототипа.
